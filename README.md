# opencode-council

Каскадная схема «совет» для OpenCode V2: дорогая модель принимает решения, средняя пишет код, дешёвые проверяют и сортируют.

Установка одной командой, удаление — одной. Ничего не перезаписывает молча.

```
council (primary, deepseek-v4-pro)
├── architect  kimi-k3.1-pro     планирует, решает, кода не пишет
├── reviewer   gemini-4-argon    ревью диффа, писать не может
├── triage     gpt-6-luna        тесты → список причин
└── explore    gpt-6-luna        поиск по коду (встроенный агент)
```

Плюс служебные модели: `general` и `compaction` → `deepseek-v4-pro`, `title` и `summary` → `deepseek-v4.1-flash`.

---

## Зачем это

Одна модель на всё — это либо дорого, либо глупо. Здесь разделено по цене ошибки:

| Роль | Что делает | Почему эта модель |
|---|---|---|
| `council` | пишет код, зовёт остальных в трёх точках | сильная, но не самая дорогая |
| `architect` | план до первой правки, разбор повторной ошибки, приёмка | решения важнее скорости набора |
| `reviewer` | ищет поломки в диффе | чужая модель видит то, что автор пропустил |
| `triage` | гоняет тесты, группирует падения | работы много, думать почти не надо |

`council` зовёт `architect` ровно три раза: перед первой правкой файлов, после второй одинаковой ошибки и перед словом «готово». `reviewer` — один раз, на готовый дифф. Не «на всякий случай».

## Требования

- OpenCode V2
- Windows PowerShell 5.1 или PowerShell 7+
- Подписка или ключи для моделей `opencode-go/*` (см. [Смена моделей](#смена-моделей))
- Для `reviewer` и `triage` — git-репозиторий в рабочей папке (они читают `git diff` / запускают тесты)

## Установка

```powershell
cd путь\к\opencode-council
.\install.ps1
```

Что произойдёт:

1. `agents\*.md` → `~/.config/opencode/agents/`
2. `commands\*.md` → `~/.config/opencode/commands/`
3. в `opencode.json` добавляется блок `agents` с моделями — **только для агентов, у которых модели ещё нет**

Безопасность важнее удобства, поэтому:

- существующие файлы с другим содержимым не затираются, а сохраняются в `*.bak-ГГГГММДД-ЧЧММСС`;
- повторный запуск ничего не дублирует;
- если у агента уже прописана своя модель, установщик её не трогает;
- если в конфиге есть комментарии (`//` или `/* */`), файл **не перезаписывается** — скрипт скажет, что дописать руками.

Полезные ключи:

```powershell
.\install.ps1 -DryRun                   # показать, что будет сделано, и ничего не менять
.\install.ps1 -SkipModelOverrides       # только файлы агентов, конфиг не трогать
.\install.ps1 -Target D:\proj\.opencode # поставить не глобально, а в проект
```

Если `opencode.json` нет вообще — установщик создаст его с `$schema` и блоком `agents`.

## Проверка

```powershell
opencode debug agents     # в списке должны быть council, architect, reviewer, triage
opencode reload
```

Пощупать без риска:

```
/plan добавить кэш для ответов API
```

Должен ответить только планом, без правок. Если ответил кодом — `architect` не подхватился, смотри `opencode debug agents`.

Затем по-настоящему:

```
/советник переписать загрузку настроек, сейчас падает на пустом файле
```

Ещё вариант — `Shift+Tab` до `council` и работать в нём как в обычном агенте.

## Что где лежит

```
opencode-council/
├── agents/
│   ├── council.md      primary, оркестратор
│   ├── architect.md    планировщик, edit/shell/execute запрещены
│   ├── reviewer.md     ревьюер, только чтение + git diff/status/log/show
│   └── triage.md       тесты, только известные test-команды
├── commands/
│   ├── советник.md     /советник — вся схема
│   ├── plan.md         /plan — только архитектор
│   ├── review.md       /review — только ревьюер
│   └── triage.md       /triage — только тесты
├── lib/JsonText.ps1    сериализатор JSON (2 пробела, без \uXXXX)
├── tests/run-tests.ps1 44 проверки в песочнице
├── .github/workflows/test.yml  CI: Windows PowerShell 5.1 и PowerShell 7
├── install.ps1
├── uninstall.ps1
├── LICENSE
└── README.md
```

Права заданы жёстко, а не «на честном слове»:

- у `architect` запрещены `edit`, `shell`, `execute` и `subagent` — роль без права что-либо менять;
- у `reviewer` разрешён `shell` только для `git diff/status/log/show`; `execute` запрещён, иначе запрет записи обходится через `tools.opencode.worktree_remove`;
- у `triage` разрешены только команды запуска тестов плюс `git status/diff`;
- у `council` разрешены подагенты только из списка, `subagent` в целом запрещён.

## Смена моделей

Модели прописаны в двух местах.

**1. Агенты каскада** — в шапке файла:

```yaml
---
mode: subagent
model: opencode-go/kimi-k3.1-pro
---
```

Меняете строку `model:` в `agents\architect.md` (или `reviewer.md`, `triage.md`, `council.md`) — и всё. Достаточно `opencode reload`.

**2. Служебные агенты** — в `opencode.json`:

```json
{
  "agents": {
    "explore":    { "model": "opencode-go/gpt-6-luna" },
    "general":    { "model": "opencode-go/deepseek-v4-pro" },
    "title":      { "model": "opencode-go/deepseek-v4.1-flash" },
    "summary":    { "model": "opencode-go/deepseek-v4.1-flash" },
    "compaction": { "model": "opencode-go/deepseek-v4-pro" }
  }
}
```

Эти значения — просто пример под подписку OpenCode Go. Замените на свои: любой провайдер, настроенный в OpenCode, в формате `провайдер/модель`.

Если у вас нет `opencode-go`, а каскад нужен — поставьте `.\install.ps1 -SkipModelOverrides` и пропишите свои модели в шапках файлов. Схема от моделей не зависит, зависит только цена.

> **Честно про деньги.** На бесплатных моделях каскад работает, но смысла в нём мало: вы платите задержкой за каждый вызов подагента, а экономия нулевая. На платной подписке недельный лимит расходуется быстрее обычного: `architect` — тяжёлая модель, а `council` может звать его трижды за задачу. Если лимит кончился, приходит `429` (`provider.go-limit`) и всё встаёт до сброса — это не баг пакета.

## Удаление

```powershell
.\uninstall.ps1 -DryRun     # посмотреть
.\uninstall.ps1             # удалить
```

Удаляет только то, что поставил установщик:

- файлы с совпадающим содержимым;
- модели, значения которых всё ещё равны тем, что прописал установщик.

Изменённые вручную файлы и модели **остаются**, скрипт про них скажет. Нужно снести всё подчистую — `.\uninstall.ps1 -Force`.

Ваши собственные агенты, провайдеры и прочие ключи конфига не затрагиваются: если после удаления блок `agents` пуст, он убирается целиком, а остальное содержимое файла сохраняется.

## Мелкие детали, на которых спотыкаются

**«Файл не установился, ничего не произошло»**
Скорее всего в `opencode.json` есть комментарии. Это защита: сериализатор потерял бы их. Допишите блок `agents` руками из раздела [Смена моделей](#смена-моделей).

**«Кириллица в скриптах превратилась в кракозябры»**
Все `.ps1` сохранены в UTF-8 **с BOM**. Windows PowerShell 5.1 без BOM читает файл как ANSI и падает на кириллице. Не пересохраняйте скрипты «в UTF-8 без BOM».

**«Хочу вложенных подагентов глубже»**
Не выйдет: `architect`, `reviewer` и `triage` сами не могут звать подагентов (`subagent: deny`). Вложенность здесь ровно один уровень, и это сделано намеренно — иначе каскад превращается в дерево, которое невозможно ни посчитать, ни отладить.

**«Ревьюер не видит изменения»**
Он видит только закоммиченное и `git diff`. Вне git-репозитория ревью бессмысленно.

## Тесты

Установщик трогает чужой конфиг, поэтому у него есть свой набор проверок — 44 штуки, каждая в отдельной песочнице во временной папке. Ваш `~/.config/opencode` при этом не затрагивается.

```powershell
.\tests\run-tests.ps1              # прогон
.\tests\run-tests.ps1 -KeepSandbox # оставить песочницу для разбора
.\tests\run-tests.ps1 -Pack D:\другой\путь\к\пакету
```

Скрипт возвращает `0`, если всё прошло, и `1`, если упала хоть одна проверка. Дочерние процессы он запускает тем же хостом, в котором работает сам: под `powershell.exe` проверяется Windows PowerShell 5.1, под `pwsh` — PowerShell 7.

Что проверяется:

| Блок | Проверка |
|---|---|
| состав | все файлы пакета на месте |
| кодировка | каждый `.ps1` в UTF-8 с BOM (иначе 5.1 падает на кириллице) |
| шапки | у агентов есть `mode`, `model`, `description`; команды ссылаются на существующих агентов |
| установка | конфиг с нуля: создаётся, 5 моделей, файлы на месте |
| идемпотентность | второй запуск не меняет ни байта и не плодит бэкапов |
| удаление | возвращает конфиг в исходный вид, пустой `agents` убирается целиком |
| чужая настройка | руками изменённая модель не перезаписывается |
| `-Force` | изменённый файл остаётся без флага и удаляется с ним |
| JSONC | конфиг с комментариями не перезаписывается, файлы при этом копируются |
| `-DryRun` | на диске не появляется ничего |

Те же тесты гоняет GitHub Actions на каждый push и pull request (`.github/workflows/test.yml`): Windows-раннер, сначала Windows PowerShell 5.1, затем PowerShell 7.
